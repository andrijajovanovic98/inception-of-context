Goal and Role of the Bonus Module

What the bonus ideas add on top of a working Part 1-3

Developer Experience
1. Dynamic Lifecycle Reindex
  • In Part 1, ChromaDB indexes at startup, and the watcher monitors events.
  • What happens if an external git branch switch occurs or the index needs a clean slate?
  • POST /reindex re-chunks and re-embeds every file at runtime, and purges the chunks of files deleted while no watcher ran.
2. Visual Auditing Visual Diff
  • Part 3 writes whole files, but human developers must review exact code deltas.
  • The visual diff engine generates colorized, line-by-line unified diffs for the web UI.
  • Green (+) for additions, red (-) for deletions.
3. Git Commit (Opt-in) Git Commit
  • With Auto Git Commit ticked, a green patch is committed: only the patch's files, never other staged work.
  • The local model writes a Conventional Commit message from the intent and the patch summary (live: feat(calculator.py): add square method with rounding).

Dynamic Reindexing: POST /reindex

Full vector database regeneration at runtime without restarting processes or containers

Dynamic Lifecycle
Execution Steps Execution Flow
  • 1. Forget the Hashes: reset_state(), so no file is skipped as unchanged.
  • 2. Re-chunk and Re-embed: index_all(force=True) walks the target and embeds every chunk with all-MiniLM-L6-v2.
  • 3. Reconcile: chunks of files that are gone from disk are deleted, even when no watcher saw the deletion.
  • 4. Refresh and Announce: the BM25 corpus and symbol inventory are rebuilt; a REINDEX event reaches the live feed. ?full=false runs an incremental sync instead.
API Contract Sample Request / Response
# a real call against demo_app (0.49 s) $ curl -X POST http://127.0.0.1:8000/reindex { "status": "success", "message": "On-demand full reindex completed successfully", "full": true, "indexed_files": 5, "total_files": 4, "total_chunks": 23, "file_breakdown": {"calculator.py": 8, "formatter.py": 7, "main.py": 5, "ioc.config.yml": 3} } # indexed_files counts the empty __init__.py too

Visual Diff Engine: bonus/diff_engine.py

Structured, human-auditable code delta visualization in the browser

Diff Engine
How the Diff is Computed Architecture
  • Employs Python native difflib.unified_diff algorithm as the calculation backbone.
  • Categorizes lines into additions (+), deletions (-), and contextual unchanged code.
  • Counts the changed lines: the square-method patch is +4 / -0.
  • Diffs are taken against the run's pre-run originals, so a committed (green) patch still shows its diff.

Automated Git Committer: bonus/git_committer.py

Committing verified modifications with local LLM-authored conventional commit messages

Git Automation
Conventional Commit Prompting LLM Generation

The local model gets the intent, the patch summary and the touched file names (no diff), and returns one line:

Generate a single concise Conventional Commit message following the format: <type>(<scope>): <short description> Allowed types: feat, fix, refactor, test, docs, chore. Rules: - Exactly ONE line only. - Do not use quotes or markdown formatting. - Be brief and descriptive (max 72 characters). Coding Intent: {intent} Patch Explanation: {patch summary} Touched Files: {file names} Commit message:
Safe Git Operations Subprocess
  • Success Gated, Opt-in: only after a green validation, and only with Auto Git Commit ticked.
  • Precise Staging: git add -A -- <paths>, then git commit -- <paths>: other staged work stays out of the commit.
  • The hash and message come back to the dashboard; a failed commit is shown, never silent. With Ollama down the message falls back to a template.

Dry-Run Simulation Mode: Risk-Free Previews

Full patch generation, diff calculation, and sanity check audit without disk modification

Safety Mode
Why Dry-Run Matters Utility
  • Allows developers and evaluators to inspect model code reasoning before committing to disk.
  • One generation and no validation run: a quick look at what the model would change.
  • Ticked with the Dry-Run Mode box of the Patch Loop & Bonus tab, or --dry-run on the CLI.
How the Engine Handles Dry-Run Execution Logic
  • Model generates the structured JSON patch.
  • The 6 sanity checks and the guards audit the generated in-memory code.
  • The diff engine calculates the unified diff against current files.
  • Execution halts safely: zero disk writes, zero temporary files, zero test subprocesses.

Dockerization & Execution Modes (Makefile)

Simple single-command launch configurations for every evaluation context

Deployment
make bonus Target
  • Launches the unified bonus/dashboard.py service on port 8000.
  • Grants immediate access to all 4 tabs; WATCH_CONTAINER=name also starts the crash watcher.
make bonus
make up / down Compose
  • Builds and starts the container via docker-compose.yml; embedding weights and flake8 are baked into the image.
  • Serves http://127.0.0.1:8000 (host networking).
make up
Offline by Design Offline
  • HF_HUB_OFFLINE=1 with baked weights: nothing is downloaded at run time.
  • network_mode: host lets the container reach the host's Ollama on 127.0.0.1:11435; it is not a network sandbox.
  • The crash watcher runs with make bonus on the host: the container has no Docker socket (503).
Bonus B3

B3: Docker SDK Crash Watcher

Watch a target service's logs and trigger the patch loop on crash

bonus/crash_watcher.py
Docker SDK Integration bonus/crash_watcher.py
  • CrashWatcher follows one container's log stream via the Docker SDK (docker.from_env()).
  • Log tail kept in a 200-line ring buffer, shown live on the dashboard.
  • Non-zero exit code = crash; each crash handled once (keyed by FinishedAt).
Crash → Patch Loop Self-Healing
  • Log tail becomes the patch intent; stack frames rewritten to target-relative file:line in function.
  • Runs the same patch loop, lock and history as the Patch Loop tab.
  • Green patch → service restarted; red patch → left stopped for a human.
  • Consecutive crash runs capped (3) so a broken service cannot keep the model busy.
Endpoints & Makefile Run It
  • API: POST /bonus/crash-watch (start), GET (status), DELETE (stop).
  • make demo-service runs the target as a crashable service container.
  • make bonus WATCH_CONTAINER=ioc-demo-service starts the watcher.
  • Crash Watcher card in bonus/dashboard.py with live log and crash history.
