Bonus

A Bonusz modul celja es szerepe

Miert szukseges a kotelezo reszeken feluli kiegeszites a professzionalis hasznalathoz?

Developer Experience
1. Dinamikus eletciklus Reindex
  • A Part 1-ben a ChromaDB index az inditaskor epul fel, a watcher figyeli a valtozasokat.
  • De mi tortenik, ha a lemezen egy kulso git pull lefut vagy az adatbazis korrupttá válik?
  • A POST /reindex vegpont lehetove teszi a teljes adatbazis ujrageneralasat a szerver ujrainditasa nelkul.
2. Lathato valtozasok Visual Diff
  • A Part 3 teljes fajlcserevel dolgozik. De a fejleszto latni akarja, pontosan mi valtozott!
  • A vizualis diff motor soronkenti, szines unified diff nezetet general a felhasznaloi felulet szamara.
  • Zold (+) a hozzaadott, piros (-) a torolt sorokhoz.
3. Zárt CI/CD ciklus Git Commit
  • A sikeres kodgeneralas es validacio utan a kód automatikusan bekerul a Git repozitoriumba.
  • A helyi LLM elemezi a modositast, es szabvanyos konvencionalis uzenetet general (pl. feat(calculator): add power method).

Dynamic Lifecycle
A mukodes lepesei Execution Flow

Vizualis Diff Motor: bonus/diff_engine.py

Strukturált, ember altal azonnal auditálható valtozas-megjelenites a bongeszoben

Diff Engine
Hogyan epul fel a diff? Működés

Automata Git Committer: bonus/git_committer.py

Validalt valtozasok veglegesitese helyi LLM altal irt konvencionalis commit uzenettel

Git Automation
Konvencionalis commit prompt LLM Generation

A helyi Ollama modell elemzi a diffet, es general egy rovid commit uzenetet:

COMMIT_PROMPT = """ Elemezze az alabbi diffet es irjon egy szabvanyos Conventional Commit uzenetet (feat, fix, refactor): {diff_content} Formátum: feat(scope): rovid osszefoglalo """
Biztonsagos Git muvelet Subprocess
  • Csak siker eseten: A commit kizarolag akkor fut le, ha a validacio (tesztek) hibatlanul befejezodott.
  • Csak az erintett fajlok: A git add nem mindent ad hozza (nincs git add .), hanem csak a patchben szereplo fajlokat!
  • Visszaadja a commit hasht es a naplobejegyzest a feluletre.
Bonus

Dry-Run Szimulacios Mod: Kockazatmentes elonezet

Patch generalas, diff kalkulacio es sanity check ellenorzes a lemez erintese nelkul

Safety Mode
Miert fontos a Dry-Run? Hasznosság
  • A fejleszto vagy ertekelo elore latni akarja, hogy a modell milyen szinten ertette meg a feladatot.
  • Tesztelheto a kod generalasa lemeziras, fajlzarlat vagy a tesztfuttato terhelese nelkul.
  • A webes feluleten 1 kattintassal kapcsolhato az "Enable Dry-Run" kapcsoloval.
Hogyan mukodik a motorban? Logika
  • A modell legeneralja a strukturalt JSON patchet.
  • Lefutnak a 6 Sanity Check ellenorzesek az in-memory tartalmon.
  • A diff motor generalja a unified diff elonezetet a memoriaban levo eredeti es generalt kodbol.
  • A folyamat itt megall: nincs fájliras, nincs *.ioc.tmp, nincs subprocess futtatas.

Osszefoglalo es Bonusz vedesi forgatokonyv

Hogyan mutasd be a bonuszt a maximális XP megszerzesehez?

Bonus XP 125%
1. Lepes: Reindex Demo 1
  • Kattints a feluleten a Reindex gombra, vagy futtasd le a curl parancsot.
  • Mutasd meg az ertekelonek a logokban, hogy az adatbazis urulese es ujraepitese 0.3 masodperc alatt megtortent.

  • Kapcsold be az Enable Dry-Run kapcsolot es indits el egy patch feladatot.
  • Mutasd meg a szines diffet, majd fuss le egy git status-t a terminalban, bizonyitva, hogy semmi sem valtozott!
3. Lepes: Valos Commit Demo 3
  • Kapcsold ki a Dry-Runt, futtasd le a patchet.
  • A sikeres validacio utan mutasd meg a frissen letrejott Git commitot az LLM altal megfogalmazott uzenettel!
