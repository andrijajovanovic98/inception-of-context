Hibrid visszakeresés: sűrű vektorok és ritka BM25Okapi

Miért nem elég a vektoros hasonlóság forráskódra, és hogyan segít a hibrid keresés

Keresőmotor
Sűrű keresés (ChromaDB + all-MiniLM) Szemantika
  • Működés: a szöveget 384 dimenziós vektortérbe képezi, és koszinusztávolságot számol.
  • Erősség: körülírt szándék: a „how is a value formatted as currency?” kérdésre a format_currency az első (0.88).
  • Gyengeség kódon: pontos azonosítókra gyengébb: a „where is X used?” teljesen elvétheti a hívót (subject VI.2).
candidate_count = max(target_k * 3, min(total_count, 15)) chroma_res = self.db.query(query_text=query, n_results=candidate_count) dense = max(0.0, min(1.0, 1.0 - float(dist)))
Ritka keresés (BM25Okapi) Pontos kulcsszavak
  • Működés: TF-IDF-változat, amely a pontos szógyakoriságot és az inverz dokumentumgyakoriságot méri.
  • Erősség: pontos azonosítók: a „where is multiply used?” a main.py calculate_tax hívóját is rangsorolja.
  • Gyengeség: nincs szemantika: egy könnyű szótövező összevonja a ragozott alakokat (a „divides” illeszkedik a divide-ra), de szinonimát sosem talál meg.
query_tokens = tokenize_code(query) # format_currency -> # format_currency, format, currency # divides -> divid, like divide raw_bm25 = bm25.get_scores(query_tokens) bm25 = score / max(raw_bm25) # scaled to [0, 1]

Szimbólum-előfeloldás: igaz válaszok

A subject által értékelt két kérdéstípusra az index válaszol, nem a modell

Hallucináció ellen
A kihívás: kitalált szimbólumok Kockázat
  • Subject (VI.2): az „is there a function called X?” és a „what functions exist in this file?” kérdést egy kis modell könnyen elrontja; ezekre a /ask nem találhat ki az indexben nem szereplő szimbólumot.
  • Mérés a javítás előtt: a main.py függvényeire a 3B modell azt felelte: <entrypoint>, ami az indexelő neve a __main__ blokkra.
  • A tisztán generatív tokenjóslók a valószínűséget részesítik előnyben a tényszerű tagadással szemben.
Az IoC megoldása: determinisztikus előfeloldás Megoldás
  • 1. Kérdéstípusok: a resolve_symbol_query() mindkét típust felismeri a természetes változataikban: backtick, Class.method, „does X exist”, „which functions are in <file>”, és magyarul is.
  • 2. Szimbólumleltár: az indexelt AST-darabok függvényei, metódusai és osztályai a sortartományukkal; a modulblokkok nem szimbólumok.
  • 3. Az index válaszol: a csak erre a tényre irányuló kérdés el sem jut a modellig (answer_source: "index"); tágabb kérdésnél az ellenőrzött tény áll elöl, a kódban sehol nem szereplő neveket pedig megjelöli.
Védési tipp: kérdezd meg: „is there a function called sqrt?”; a jelvényen ez áll: „Answered from the index (model not consulted)”.

Hibrid pontszám-fúzió: dense + BM25

Hogyan lesz a p2/retriever.py-ban két pontszámskálából darabonként egyetlen hasonlósági pontszám

Algoritmus
A fúziós képlet Matematika

A koszinusz-hasonlóság már [0, 1]-ben van; a BM25 nem korlátos, ezért előbb elosztjuk a kérdés legjobb BM25 pontszámával. Ezután súlyozott összeg:

score = 0.5 × dense + 0.5 × bm25 / max(bm25) + 0.25 if the query names the symbol + 0.15 if the query names the file score = min(score, 1.0)
  • Jelöltek: a dense találatok és a legjobb BM25 találatok, a demó indexen mindkettőből max(3 × k, 15).
  • Egyenlő pontszámnál a fájl és a sor dönt, így egy kérdés mindig ugyanúgy rangsorol.
  • A ChromaDB marad a kanonikus tár: a BM25 korpusz minden indexváltozás után az ő dokumentumaiból épül újra.
Megvalósítás: p2/retriever.py Kód
# Retriever.retrieve(query, k=3, alpha=0.5), abridged combined_score = (alpha * d_score) + ((1.0 - alpha) * b_score) boost = 0.0 if symbol_name and (symbol_name in query_words or short_sym in query_words): boost += 0.25 if file_stem and file_stem in query_words: boost += 0.15 final_score = min(1.0, combined_score + boost) # ties break on location: a stable ranking scored_candidates.sort(key=lambda x: (-x[0], str(x[1]["file_path"]), int(x[1]["start_line"] or 0)))

Helyi LLM integráció: Ollama és qwen2.5:3b

Teljesen offline kódkövetkeztetés, külső függőségek nélkül

Helyi motor
Miért qwen2.5:3b? Modellválasztás
  • 3B paraméter: modern CPU-n is elfut, erős GPU nélkül.
  • Instruct modell: a subject a qwen2.5:3b-t javasolja a /ask-hoz; egy modell is elég, így a patch-ciklust is ez hajtja.
  • Subject: kifejezetten a ~3B paraméteres modellosztályt említi.
Ollama REST API Integráció
  • Közvetlen HTTP POST: http://127.0.0.1:11435/api/generate.
  • Nincs nehéz külső SDK: aszinkron httpx kérések.
  • Nem streamelt hívások ("stream": false), 0.1-es temperature, minden kérésnél ugyanaz a 8192-es num_ctx.
  • A szabványos :11434-re csak akkor vált, ha a :11435 elutasítja a kapcsolatot, és ezt a stderr-en jelzi.
Biztonság és izoláció Offline szabály
  • Az Ollama a hoszton fut; az alkalmazás (a make up konténerből is) csak loopbacken éri el.
  • Nincs API-token, nincs előfizetés, nincs külső internetfüggőség.
  • A védésen ellenőrizhető a hálózat lekapcsolásával vagy a forgalom vizsgálatával.

Valós idejű eseményfolyam (Server-Sent Events)

GET /events: élő frissítés a böngészőnek, periodikus lekérdezés nélkül

Reaktivitás
Miért SSE, és nem WebSocket vagy polling? Architektúra
  • Egyszerűség: tiszta HTTP folyam, kétirányú kézfogás és extra protokollréteg nélkül.
  • Beépített újrakapcsolódás: a böngésző EventSource-a kezeli a kapcsolatszakadást.
  • Nincs fölösleges forgalom: nincs folyamatos kérésáradat, mint a naiv kliensoldali pollingnál.
