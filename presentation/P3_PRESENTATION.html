Why Structured JSON and NOT Free-Form Diffs?

Addressing small language model limitations through deterministic representation

JSON Schema
Failure of Free-Form Diffs Problematic
  • Small 3B models frequently miscalculate hunk header line counts: @@ -14,6 +14,8 @@.
  • A single misplaced whitespace or indentation tab causes patch or git apply to fail.
  • Explicit subject rule: "The patch must NOT be a free-form diff."
Subject-Mandated JSON Schema Mandatory Schema
{ "summary": "Add divide method with zero-check", "files": [ { "path": "calculator.py", "op": "modify", "content": "class Calculator:\n def add..." } ] }

For modify operations, content represents the complete, post-change file, not an ambiguous partial fragment!

The 6 Mandatory Sanity Checks (Immediate Refusal)

Rigorous AST and heuristic pre-flight checks executed by p3/validator.py prior to disk writes

Hard Refusals
# Sanity Check Why It Fails (Subject Rationale) Detection Technique
1 Retrieval marker leakage Model echoes prompt headers like [SOURCE 1]: or --- CODE CHUNKS --- into code. Regex pattern scanning on generated file content.
2 Creating existing file Using create on a file that already exists on disk risks silent overwrite. Filesystem check: os.path.exists(path).
3 Empty or null replacement Replacing non-empty code with "", "None", or "null" causes file loss. Length and literal keyword check.
4 Stub-only functions Model emits lazy placeholder bodies: pass or raise NotImplementedError. AST analysis: function body must not contain only Pass/Raise nodes.
5 File shrinkage (> 60%) Drastic unexpected size reduction signals code loss or truncated output. Check: len(new) < len(old) * 0.4.
6 More than 3 files modified Preventing runaway hallucinations: 1 patch is limited to at most 3 source files. Check: len(patch["files"]) > 3.

Atomic Staging and Snapshotting

Guaranteeing filesystem integrity against crashes and partial write failures

Atomic Safety
Step 1: In-Memory Baseline Snapshot Snapshot
  • Before touching disk, exact contents of all targeted files are cached in memory.
  • For newly created files, the system records that rollback must delete the file.
snapshots[file_path] = file_path.read_text()
Step 2: *.ioc.tmp Staging & os.replace Atomicity
  • Generated content is first written to temporary sibling files: calculator.py.ioc.tmp.
  • Only after all files stage successfully does the system execute POSIX atomic swaps: os.replace(tmp_path, target_path).
  • There is never a corrupted intermediate state on disk if a process terminates abruptly!

Self-Healing Retry Loop: Autonomous Error Feedback

Feeding compiler tracebacks directly back to the local model to correct mistakes

Retry Engine
Attempt 1 Fails (Traceback Intercepted) Failure

Suppose Attempt 1 introduces a typo in an exception identifier:

Traceback (most recent call last): File "calculator.py", line 18 except ZeroDivisionErrorr: ^ SyntaxError: invalid syntax

Rather than aborting, this exact compiler diagnostic is captured and structured into the retry prompt!

Attempt 2: Targeted Correction Prompt Correction
RETRY_PROMPT = f""" The previous patch failed project validation! ERROR OUTPUT: {captured_stderr} TASK: Fix the reported error and return the corrected complete file contents in the required JSON format! """
Part 3

100% Rollback Guarantee: Zero Code Corruption

A non-negotiable peer evaluation requirement: the repository must never be left in a broken state

Fail-Safe
When Does Rollback Trigger? Triggers
  • Attempts 1, 2, and 3 all fail project validation.
  • Sanity check hard refusal cannot be resolved.
  • Unexpected runtime exception occurs during file staging.
How Does Rollback Execute? Mechanism
  • Snapshotted content is atomically restored via os.replace.
  • Created files (op: create) are deleted from disk.
  • All leftover *.ioc.tmp artifacts are removed.
Peer Evaluation Proof Audit
  • Running git status and git diff demonstrates an entirely clean working tree.
  • Zero stray files or altered source lines remain after failed attempts!

Walkthrough: Self-Healing in Action (Retry Loop)

How the autonomous system repairs errors without human intervention

Self-Healing Trace
Attempt 1: Failure Attempt 1 (Fail)
  • The model generates the divide method but leaves an unclosed docstring quotation.
  • Validation aborts: SyntaxError: unterminated string literal.
  • The system captures the traceback and constructs a targeted corrective retry prompt.
Attempt 2: Recovery Attempt 2 (Success)
  • The model analyzes the SyntaxError location from the feedback.
  • Closes the string literal and emits corrected complete file contents.
  • Validation re-executes: EXIT CODE 0. The patch is verified and applied!
