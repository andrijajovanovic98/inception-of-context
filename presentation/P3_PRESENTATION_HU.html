INCEPTION OF CONTEXT - 3. RESZ

Patch generalas es Onjavito ciklus

Strukturalt JSON, 6 AST Sanity Check, Atomikus kezeles es Rollback

A 3. reszben az IoC egy autonom kodolo agensse valik. A felhasznaloi szandekbol kiindulva kontextust gyujt, strukturalt modositast general, szigoruan ellenorzi azt a lemezre iras elott, kiertekeli a projekt tesztjeit, es hiba eseten 3 kiserleten at onjavitast vegez - vagy 100%-ban visszagorgeti az eredeti allapotot.

Mukodesi modell Autonom Ciklus (Loop)
Eloszures 6 AST Sanity Check
Onjavitas Max 3 probalkozas
Biztonsag 100% Atomikus Rollback
Part 3

A 3. resz specifikacioja: Ez egy CIKLUS

Mit kovetel meg a hivatalos subject a harmadik fazisban?

Subject Audit
Nem kulonálló vegpontok The Loop
  • A subject kulcsmondata: "This is a LOOP, not merely separate endpoints."
  • Egyetlen felhasznaloi szandek (pl. "add healthcheck route") inditja el a teljes folyamatot.
  • A rendszer onalloan iteral a sikerig vagy a biztonsagos visszagorgetesig.
Szigoru elozetes szures Sanity Checks
  • Zéró lemeziras ellenorzes nelkul: A generalt patch nem kerulhet kozvetlenul a forrasfajlokba.
  • 6 kotelezo elutasitasi ok: Csonka fuggvenyek (stubs), meretzsugorodas, szivargo prompt markerek stb.
  • Szintaktikai es logikai vizsgalat AST segitsegevel.
Validacio es Visszagorgetes Safety First
  • ioc.config.yml: Kulso konfiguracio alapjan futtatott forditasi es teszt parancsok.
  • 3 javito kiserlet: Forditasi hiba eseten a traceback visszakerul az LLM-nek.
  • Garantalt Rollback: Ha mindharom kiserlet elbukik, a fajlrendszer pontosan visszaall.
Part 3

Az Autonom Patch-Ciklus lepesrol lepesre

Hogyan halad a vezerles a felhasznaloi szandektol az atomikus commitig?

Control Flow
1. Lepes Szandek es Kontextus p3/generator.py A felhasznalo kerese alapjan hibrid keresessel osszegyujtjuk az erintett forrasfajlokat.
->
2. Lepes Strukturalt JSON Patch qwen2.5:3b A modell nem diffet, hanem teljes feluliro tartalmat ad JSON formatumban.
->
3. Lepes 6 Sanity Check p3/validator.py AST es heurisztikus ellenorzes. Ha barmelyik serul: azonnali refusal.
4. Lepes Snapshot es *.ioc.tmp p3/applier.py Memoria/fajl mentes az eredeti allapotrol. Ideiglenes fajlok letrehozasa.
->
5. Lepes Validacio (ioc.config.yml) Subprocess Futtatjuk a forditasi es teszt ellenorzeseket. Siker eseten vege!
->
6. Lepes Hiba & Onjavitas vagy Rollback Self-Healing Hiba traceback vissza az LLM-nek (max 3x). Ha elfogy a probalkozas: 100% Rollback.
Part 3

Miert strukturalt JSON es miert NEM szabad diff?

A kis méretű nyelvi modellek matematikai korlatai es a robusztus kódgenerálás

JSON Schema
A szabad diff (Unified Diff) bukasa Problemás
  • A 3B-s modellek szinte mindig elrontjak a diff fejlecek sorszamait: @@ -14,6 +14,8 @@.
  • Ha 1 karakterrel elcsuszik a whitespace vagy a tabulator, a patch vagy git apply hibaval elszall.
  • A subject kifejezetten megtiltja: "The patch must NOT be a free-form diff."
A subject altal elirt JSON schema Eloiras
{ "summary": "Add divide method with zero-check", "files": [ { "path": "calculator.py", "op": "modify", "content": "class Calculator:\n def add..." } ] }

A modify muvelet eseten a content a fajl teljes, vegleges tartalmat jelenti, nem pedig toredeket!

Part 3

A 6 kotelezo Sanity Check (Azonnali elutasitas)

A p3/validator.py altal vegzett szigoru AST es heurisztikus audit a lemezreiras elott

Hard Refusals
# Ellenorzes neve Miert veszelyes? (Subject indoklas) Hogyan detektaljuk?
1 Prompt marker szivargas Az LLM visszamasolja a [SOURCE 1]: vagy --- KODRESZLETEK --- cimkeket a kodba. Regex mintaillesztes a generalt tartalomban.
2 Letezo fajl felulirasa 'create'-tel A create opcioval nem szabad letezo fajlt felulirni (adatsérülés veszelye). os.path.exists(path) vizsgalata.
3 Ures/Null csere Non-empty fajlt tilos "", "None" vagy "null" szovegre cserelni. Hossz es kulcsszo vizsgalat.
4 Stub-only fuggvenyek A modell csak csonka fuggvenyeket general: pass, raise NotImplementedError. AST elemzes: a fuggvenytorzs nem lehet pusztan Pass/Raise csomopont.
5 Meretzsugorodas (> 60%) Ha egy letezo fajl merete tobb mint 60%-kal csokken, az kodvesztest jelez. len(uj_kod) < len(regi_kod) * 0.4 ellenorzes.
6 Tobb mint 3 fajl modositasa A scope robbanas megelozese: 1 patch maximalisan 3 forrasfajlt erinthet. len(patch["files"]) > 3 elutasitas.
Part 3

Atomikus modositas es Pillanatkep (Snapshotting)

Hogyan garantaljuk a fajlrendszer serulesmentesseget barmilyen hiba eseten?

Atomic Safety
1. Lepes: Pillanatkep keszitese Snapshot
  • Mielott barmely fajlhoz hozzaernenk a lemezen, a rendszer elmenti az erintett fajlok pontos tartalmat a memoriaba vagy a .ioc_snapshots/ tarba.
  • Uj fajl letrehozasa eseten feljegyzi, hogy a rollback soran a fajlt torolni kell.
snapshots[file_path] = file_path.read_text()
2. Lepes: *.ioc.tmp es os.replace Atomicitás
  • A kod eloszor egy ideiglenes calculator.py.ioc.tmp fajlba irodik ki.
  • Csak miutan az osszes fajl hiba nelkul kiirasra kerult, hajtjuk vegre a POSIX atomikus atnevezest: os.replace(tmp_path, target_path).
  • Nincs olyan koztes allapot, ahol egy fajl felig ki van irva, vagy a folyamat megszakadasakor serult marad!
Part 3

Validacios motor es az ioc.config.yml

A projekt-specifikus ellenorzesek levalasztasa az IoC motorjarol

Config Driven
A konfiguracio: demo_app/ioc.config.yml YAML Spec
version: 1 validation: command: "python3 -m py_compile {files} && python3 main.py" timeout_seconds: 15 stop_on_first_failure: true
  • A {files} helyere dinamikusan az erintett fajlok kerulnek.
  • Nem csak forditast (py_compile), hanem fuggosegi tesztet vagy a main.py lefutast is ellenorzi!
Hogyan futtatja a p3/validator.py? Subprocess
  • Aszinkron subprocess hivas: asyncio.create_subprocess_shell.
  • Idotullepes vedelem (timeout guard): ha vegtelen ciklus keletkezik a generalt kodban, a rendszer leallitja a folyamatot.
  • Kimenti az exit_code-ot, valamint az egesz stdout es stderr hibacsatornat.
Part 3

Onjavito ujraprobalkozasi ciklus (Self-Healing Loop)

A forditasi vagy futasi hiba visszataplalasa az LLM szamara hibajavitasra

Retry Engine
1. Kiserlet elbukik (Traceback elkapasa) Kudarc

Tegyuk fel, hogy az 1. kiserletnel a modell elgepelte a kivetel nevet:

Traceback (most recent call last): File "calculator.py", line 18 except ZeroDivisionErrorr: ^ SyntaxError: invalid syntax

Ahelyett, hogy a rendszer feladna, ezt a pontos traceback-et injektalja a kovetkezo promptba!

2. Kiserlet: Celzott javito prompt Javitas
RETRY_PROMPT = f""" Az elozo patch alkalmazasa UTAN a validacio elbukott! HIBAUZENET: {captured_stderr} KERES: Javitsa ki a szintaktikai hibat, es adja vissza a javitott fajlt teljes egeszeben a megszokott JSON formatumban! """
Part 3

100% Visszagorgetesi Garancia (Rollback)

A 42 ertekeles egyik legfontosabb sarokkove: a kodbazis soha nem maradhat hibas allapotban

Fail-Safe
Mikor fut le a Rollback? Kriteriumok
  • Ha az 1., 2. es a 3. kiserlet is elbukik a validacion.
  • Ha a Sanity Check (a 6 refusal) valamelyike ervenyesul es a modell nem tudja orvosolni.
  • Ha barmi varatlan rendszerkivetel lep fel a folyamat soran.
Hogyan all vissza a rendszer? Mechanizmus
  • A snapshotban tarolt eredeti tartalmat visszaallitjuk atomikus os.replace hivassal.
  • A letrehozott uj fajlokat (op: create) azonnal letoroljuk.
  • Az ideiglenes *.ioc.tmp fajlokat maradektalanul eltakaritjuk.
A vedes bizonyiteka Audit
  • A git status es git diff futtatasaval a vedonel azonnal lathato: a kodbazis tokeletesen tiszta maradt.
  • Egyetlen bajtnyi szemét sem marad vissza a sikertelen kiserletbol!

Part 3

Bemutato: Ongyogyulas mukodes kozben (Retry Loop)

Hogyan javitja ki magat az autonóm agens mennesi beavatkozas nelkul?

Self-Healing Trace
1. Kiserlet: Elbukik Attempt 1 (Fail)
  • A modell generalja a divide metodust, de elfelejti lezarni az idezojeles docstringet.
  • A python3 -m py_compile elszall: SyntaxError: unterminated string literal.
  • A rendszer NEM dobja el a folyamatot: a hiba bekerul a retry promptba.
2. Kiserlet: Sikeres javitas Attempt 2 (Success)
  • A modell latja a SyntaxError hibauzenetet es a sorszamot.
  • Javitja a string lezarasat, majd ujra bekuldi a teljes fajlt.
  • A validacio lefut: EXIT CODE 0. A patch sikeresen elfogadva!
